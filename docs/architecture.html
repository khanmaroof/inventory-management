Factory Inventory Management System

A demo full-stack app: a Vue 3 single-page app reads from a FastAPI service, and that service serves JSON seed data held in memory. There is no database, no auth backend, and nothing is written back to disk.

Three tiers on one machine. The browser talks straight to the API over CORS, with no proxy.

Data flow: a filtered request

What happens when a user changes a filter in the top bar, using the Dashboard as the example.

01
FilterBar
Writes to singleton refs in useFilters: period, location, category, status
02
View watcher
The view calls getCurrentFilters(); period is passed through as month
03
api.js
Drops 'all' values, builds the query string, and sends an axios GET
04
FastAPI
apply_filters → filter_by_month over the in-memory lists
05
Pydantic
Validates and serialises the response into JSON
06
Computed
Raw data goes into refs; KPIs and charts come from computed()

State model

  • Global: filter refs are declared at module scope in useFilters.js, so every view shares them
  • Global: the locale ref lives in useI18n.js and is saved to localStorage
  • Mock: useAuth.js holds a hard-coded user and task list
  • Per view: fetched data goes into local refs, and everything derived is computed
  • No Pinia or Vuex

Observations

Places where the code and its wiring don't line up, found while reviewing it for this page.

Missing endpoints. api.js calls /api/tasks (GET/POST/PATCH/DELETE) and /api/purchase-orders, but main.py defines neither. Task actions in App.vue will get a 404.
Unresolved component. Dashboard.vue uses <PurchaseOrderModal>, but the component is never imported and no such file exists in components/.
Orphaned view. views/Backlog.vue exists, but main.js has no route for it.
Hard-coded URLs. The API base http://localhost:8001 is written into api.js and again into Reports.vue.
Fixed date range. Quarter filtering only knows 2025 (QUARTER_MAP). The dashboard's backlog count ignores filters.
